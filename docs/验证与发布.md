# 验证与发布

## 工具链与版本

当前配置为 Gradle Wrapper 8.12、AGP 8.7.0、Kotlin 1.9.0，compileSdk 35、minSdk 23，
示例 targetSdk 35，Java/Kotlin 字节码目标 17。这些是仓库配置值，不代表最新版本。
SDK、插件和依赖版本以 `gradle/libs.versions.toml` 为准；Wrapper 版本在其 properties 文件。
准备兼容 AGP 的 JDK（17 或更高兼容版本）和 Android SDK，在未提交的 local.properties 配置 sdk.dir。

## 本地验证

```bash
./gradlew :anydoor:assembleRelease :sample:assembleDebug :sample:assembleDebugAndroidTest
./gradlew :anydoor:testDebugUnitTest :anydoor:lintRelease
./gradlew :anydoor:generatePomFileForReleasePublication
```

| 文件/目录 | 用途 |
| --- | --- |
| anydoor/build/outputs/aar/anydoor-release.aar | SDK 产物 |
| anydoor/build/libs/anydoor-sources.jar | 去重后的源码包 |
| sample/build/outputs/apk/debug/sample-debug.apk | 默认示例 |
| sample/build/outputs/apk/androidTest/debug/sample-debug-androidTest.apk | 仪器化测试 APK |
| anydoor/build/test-results/testDebugUnitTest/ | 单元测试 XML 证据 |
| anydoor/build/reports/tests/testDebugUnitTest/ | 单元测试报告 |
| anydoor/build/reports/lint-results-release.html | SDK Lint 报告 |
| anydoor/build/publications/release/pom-default.xml | Maven 元数据 |

测试职责：

- AnyDoorTest：门面适配、初始化、可选回调、本地绑定和显式重新注册。
- AdsSourceApiTest：直接编译文档源码，验证参数原值、布尔结果、失败行为与注册/注销。
- ConnectionTest：冷连接并发、连接死亡与重新发现。
- RegistryTest：延迟死亡通知、注册失败重试、并发注册注销。
- AnyDoorServiceTest：入参校验、代理往返、责任链、有界队列及异常回调。
- PayloadTest：API 23/33 载荷、自定义类型、Map 深度边界和循环引用。
- ProtocolTest：API 23/33 结果编码、业务 Map、旧载荷回退及不支持事务。
- ProviderTest：服务发现、服务身份与调用。

Robolectric 的本地代理往返不等同于真实系统跨进程 Binder。

## 设备验证

先检查 `adb devices -l` 和有超时保护的系统属性查询，确认设备真正响应，不自动重启共享模拟器。
在可用设备上分别执行：

```bash
./gradlew :sample:connectedDebugAndroidTest
./gradlew :sample:connectedDebugAndroidTest -PanydoorProcess=:anydoor
```

CrossProcessTest 验证主进程注册、远端同步/异步调用及注销。
RemoteEndpointTest 验证子进程注册、嵌套 Map、回调、注销、处理器进程重启后重新注册，
并包含 100 次预热、1000 次带断言的延迟采样。该采样不是竞品基准。
中心进程死亡并恢复的真实设备用例仍需补齐，不能用处理器进程重启测试代替。

## 本地发布与迁移

```bash
./gradlew :anydoor:publishReleasePublicationToMavenLocal
```

发布坐标 `com.anydoor:anydoor:0.1.0`，包含 Release AAR 和源码包。
当前只配置本地 Maven 发布，生成 POM 或构建通过不代表完成公共仓库发布。
裸 AAR 不自动解析依赖；优先使用 Maven 元数据。
包名、服务描述符和回调签名迁移要求见 [API 与接入](API与接入.md)。

迁移后核对 AAR 类路径、sources JAR、合并 Manifest、POM 和 consumer 混淆规则，
避免旧包名残留。对外发布前确认源码授权，不能将重命名视为清除来源责任。

## 生产门槛

亿级装机目标需要以下证据，不以“架构清晰”或“单测通过”替代：

- 覆盖宿主支持的系统、厂商、低内存设备及 R8 后集成。
- 分别验证中心与处理器进程死亡、注册恢复、长时间运行和反复启停。
- 覆盖队满、慢处理器、慢回调、大载荷和异常对象序列化。
- 按真实拓扑和载荷采样冷连接、热调用 P50/P95/P99、内存、线程、拒绝率。
- 宿主记录崩溃、ANR 和业务失败，分阶段灰度并准备回滚。

当前没有 SDK 级超时/取消、注册确认结果或结构化错误回调。
Map 深度保护不覆盖任意 Parcelable/Serializable/Bundle 的内部对象图，也不限制总字节数。
