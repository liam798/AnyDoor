# 目录与职责

本文描述当前源码结构，不保留历轮重构目录。使用方法见 [API 与接入](API与接入.md)。

## 工程结构

```text
anydoor/                         Android SDK、混淆规则与 Maven 发布配置
  src/main/AndroidManifest.xml  Provider 声明
  src/main/java/com/anydoor/
    AnyDoor.kt                  唯一客户端入口
    AnyDoorProvider.kt          Android 组件与服务发现入口
    CallHandler.kt              公开处理器契约
    CallResult.kt               公开处理结果
    internal/
      AnyDoorConnection.kt     服务发现、连接缓存与按需重连
      AnyDoorService.kt        唯一服务端入口、当前调用执行策略
      HandlerRegistry.kt       注册、快照与死亡清理
      ipc/
        IAnyDoorService.java   服务 Binder 契约
        ICallHandler.java      处理器 Binder 契约
        ICallCallback.java     结果回调 Binder 契约
        CallPayload.kt         Parcel 载荷
        CallResultProtocol.kt  责任链结果编码
  src/test/                     本地单元测试
sample/                         独立示例应用
  src/main/                     主进程及 :remote、:endpoint 组件
  src/androidTest/              系统 Binder 仪器化测试
gradle/libs.versions.toml        SDK、插件和依赖版本
gradle/wrapper/                  Gradle Wrapper
docs/                           接入、架构、验证说明
  examples/ads/                 源码 API 接入示例，仅纳入本地测试，不进入 SDK 发布物
.learnings/                     工程经验、历史故障和需求记录
```

## 组件所有权

| 组件 | 持有状态 | 不负责的内容 |
| --- | --- | --- |
| AnyDoor | 当前连接、本进程处理器与 Binder 的绑定 | 服务端排队、业务状态 |
| AnyDoorProvider | 唯一 AnyDoorService 实例 | 数据 CRUD、业务路由策略 |
| AnyDoorConnection | ContentResolver、发现 URI、存活服务快照 | 处理器注册恢复、调用重放 |
| AnyDoorService | 注册表、有界单线程执行器 | 任意业务功能、持久化、保活 |
| HandlerRegistry | 按 ID 和 Binder 索引的记录、死亡通知 | 执行业务、客户端对象生命周期 |
| IPC 包 | 事务、编解码规则 | 宿主公开 API、业务决策 |

服务和连接使用 `AnyDoor` 前缀，表达整体服务角色；调用契约仍使用 `Call` 前缀。
这不是承诺新增功能，也不改变 SDK 当前仅负责跨进程调用的范围。

## 依赖方向

```text
AnyDoor -> AnyDoorConnection -> Provider 发现 -> IAnyDoorService
AnyDoorProvider -> AnyDoorService -> HandlerRegistry
AnyDoorService -> ICallHandler -> 宿主处理器
AnyDoorService -> ICallCallback -> AnyDoor 适配的函数回调
```

热调用复用缓存服务，不重复访问 Provider。IPC 各端在同进程时可直接返回本地接口。
不设置单类 client 包和纯转发 server 层；三个运行组件直接位于 internal。
IPC 单独成包，集中管理 Binder 事务、类加载器和序列化兼容。
根包只有宿主契约和必须由 Manifest 引用的 Provider，内部实现不作为稳定接入点。

## 状态与锁

AnyDoor 的 Binding 持有宿主处理器、稳定 Binder 回调和注册所在服务。
HandlerRegistry 的 Record 持有中心看到的远程 Binder 和对应死亡通知。
两者分属不同进程视角，不合并成全局注册管理器。

初始化幂等；连接使用 volatile 快照和冷连接锁。客户端注册/注销在本地绑定锁内执行同步 IPC，
服务端注册表使用短临界区，业务调用基于快照并在注册表锁外执行。
注销不撤销已取出的快照，不能据此取消在途业务。

注册表以 Binder 身份去重，并校验死亡通知所属记录，防止延迟旧通知删除新注册。
AnyDoorService 的异步队列按实际入队顺序串行执行；同步调用不经过该队列。

未来只有在新增能力已被批准且存在独立状态、生命周期或执行策略时才拆组件；
不为假设需求引入二级门面、通用管理器或 Context 容器。
