# 工程经验

## 2026-09-12：通信异常不等于未执行

处理器可能已完成副作用，仅在回包前死亡。责任链不能把通信失败当作 Skip；
清理死亡注册后仍须终止当前请求，不能自动向下一处理器重复投递。
注销前的 Binder 存活检查也存在竞态，注销事务中的死亡异常须释放本地强引用；
其他存活服务异常保留绑定供显式重试。同步、异步及注销竞态均需回归测试。

## 2026-09-12：第三方源码接入边界

第三方提供面向 APP 的 `<模块名>Api` 源码，规范约束公开入口及通信契约，
不约束 SDK 内部类名、文件名、方法名或分层，也不强制单独建接入类。
示例中的 AdsEndpoint 只是参考命名，不能提升为第三方接入要求。

## 2026-09-11：跨进程注册身份

同一个处理器的注册和注销事务可能生成不同的 ICallHandler.Proxy 实例，
注册表必须比较底层 IBinder，而不是 Java 代理对象。死亡回调清理还应避免旧记录删除新记录。

## 2026-09-12：递归载荷与发布产物

Map 的写入、读取和 describeContents 必须使用一致的递归深度边界；深度限制不等于字节限制，
也不覆盖自定义 Parcelable、Serializable、Bundle 内部实现。结果协议包装应计入层数。

包名与文件名迁移应同时核对源码路径、Manifest、混淆规则、POM 和实际 AAR/源码包，
而不是仅做文本替换。Android/Kotlin 源集重叠会使源码 JAR 出现重复条目，
应在源码归档任务中去重并检查最终 ZIP 条目。
